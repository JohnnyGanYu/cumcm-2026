# B 题离线演练环境

在**没有官方模拟器**的机器上无限次演练机器狗策略。官方模拟器是最终判据；
本目录任何行为与官方不一致处，以官方实测为准。

## 模块

| 文件 | 作用 |
|---|---|
| `arena.py` | 按题面 + 附件1/2 复刻的仿真核心（案例生成、检测/清除判定、计时） |

| `directional.py` | 问题 4：定向源候选集合 `(x, y, 朝向)` 推理与信息增益补测点选择 |

| `rehearse.py` | 批量演练与统计 |

## 策略要点与实测教训

1. **必须逐步逼近，不能远距离一次定位。** 示向度误差 ±1°，在 r 处横向误差约
   0.0175 r：1500 m 处约 26 m，超过 20 m 清除半径；100 m 处仅 1.7 m。策略"边靠近
   边重测"，让几何误差随距离自然收缩。

2. **dog-leg 必须沿示向度方向前进，不能横向平移。** 横向平移会走出有效接收半径，
   实测导致远距离源大量丢失（清除率一度只有 45%）。沿示向度前进单调靠近目标，
   信号只会更强，用小角度偏移换交会角。

3. **环形补扫是主路径，不是兜底。** 实测约 51% 的干扰源站在原点收不到信号。
   环参数按"最坏覆盖间隙 < 接收半径下限 1000 m"直接选：原点 + 半径 1250 m 的 12
   个站位，最坏间隙 670 m，13 个站位即可覆盖全域；双环 23 站位成本高 77% 而收益有限。

4. **检测预算要分"搜索"和"归航"两段。** 定向源在找到信号前可能烧掉几十次检测。
   若用同一个预算，会出现"刚拿到示向度就被判预算耗尽而放弃"（实测 seed 3004 ch20：
   已测得距真值 413 m 的示向度、候选压缩到 2 个格点，却被判死）。拿到首个示向度后
   归航额度重新起算。

5. **定向源靠推理 + 盲清除，不靠加密站位。** 盲扫有天花板：37 个站位仅 98.7% 可见率
   且成本翻倍。改用两步：
   - "检测无信号"是约束——距离 ≤ 1000 m 时无信号即意味着观测点在辐射扇区之外，
     据此在 `(位置, 朝向)` 离散网格上排除矛盾状态（实测 10 次沉默观测把 8508 个
     候选压到 2166，真值始终保留）；
   - `/clear` 判定只看距离、与辐射方向无关，因此对候选格点直接盲清除。
     漏失的定向源全部"物理可解"（可见扇区一直延伸到源身边 4-10 m，但仅占目标区域
     0.1%-19%），盲清除把全清局数从 11/20 提到 17/20。

6. **`_probe_candidates` 不能只用候选源位置当观测点。** 定向源朝区域外辐射时，
   能看见它的点位于源的外侧（沿其朝向前方），未必是候选源位置本身。

## 与官方模拟器对接

`client.py` 直接指向 `http://127.0.0.1:2026` 即可用于官方模拟器（同机运行，
接口只监听回环）。正式测试前务必：

- 用演练模式（不限次数）跑通全流程，确认协议字段、超时和异常分支；
- 检查 `/enter` 返回的 `remaining_real_duration_s`，不要假定固定 1200 s；
- 自行保存完整指令与响应序列（`client.dump_log`），模拟器不提供该功能；
- 问题 3/4 各只有 3 次正式测试机会，且 9/13 17:30 之后不能开新测试。

## 本仿真器所做的假设（写入论文须声明）

题面与附件未明确、由本实现设定的部分：

1. 示向度误差在 [-1, 1] 度内，按检测点位置确定性生成（同一地点重复检测读数一致）；
2. 定向源辐射扇区为朝向两侧各 90 度、含边界；
3. 案例生成中干扰源位置在目标区域内均匀分布，有效接收半径在 [1000, 1500] m 内均匀分布；
4. 清除判定只看平面距离 ≤ 20 m，与辐射方向和频道切换无关。
