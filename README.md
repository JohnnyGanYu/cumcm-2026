## 题目要点

机器狗在半径 1800 m 的圆形区域内搜索并清除未知数量的无线电干扰源。每个频道
（1–20）至多一个干扰源，有效接收半径不低于 1000 m。检测得到示向度（含 ±1° 误差），
清除半径 20 m。通过 HTTP+JSON 接口对接官方模拟器（`127.0.0.1:2026`）。

时间成本：检测 5 s、清除 3 s、移动按距离折算；虚拟时间上限 360000 s，程序运行
时间上限 1200 s。**评分指标 = 虚拟时间 / 清除个数**（平均定位清除时间，越小越好）。

问题 1、2 为解析与算法设计；问题 3（全向源）、问题 4（含定向源）需实机测试。

### 几何内核 `src/b_sim/geometry.py`（Q1 / Q2）

- **输入契约与退化处理（R1.2 / R1.4 / R1.6）**：`localization_polygon` / `localization_region` 对 `N<2` 观测显式抛错（此前静默返回空）；楔形之交为空或面积 ≤ 1e-9 时返回带"交会为空"指示的空区域；单点 / 共线退化有明确直径与覆盖判定。
- **直径确定性（R1.5）**：多个并列最大顶点对时，确定性返回按顶点索引升序的首个。
- **外接圆覆盖判定改造（R1.7 / R1.8）**：`circle_on_diameter_covers` 从返回"比值"改为返回**带符号覆盖裕度** `margin = D/2 − max‖v−M‖`（米）；据此给出"直径圆不一定覆盖区域"的结论，并以正三角形反例（第三顶点距中点 0.866L > L/2）与 Jung 平面上界 `r* ≤ D/√3` 佐证。
- **补齐 Q2 缺口**：新增 `second_point_candidates`（沿示向度前进 + `{32°,16°,0°}` 小角度偏移、逐级退让，此前只在 `b_q2.py` 有 numpy 分析版）、`classify_second_point_candidates` / `select_second_point`（交会角 `α∈[60,120]`、`d2≤1000 m`、`‖p2‖≤1800 m` 有效性判定与"显式不可行"失败语义）、`crossing_angle_deg`、`second_point_candidate_region` / `in_second_point_region`（候选区域界定，R2.7）。

## TSP 收益上限：−28%

同一脚本给出理论下界（L1/L2 精确 Held-Karp，L3 启发式解/MST 下界 = 1.064，
L4 由"实际轨迹是可行解"保证合法）：

| 口径 | 平均定位清除时间 | 相对实际 |
|---|---|---|
| 实际 | **1397.4 s** | — |
| L4 只改访问顺序 | **1004.1 s** | **−28.1%** |
| L3 完美覆盖+摸源 | 673.6 s | −51.8% |

## 策略要点

四条结论都由实测撞出来，不是先验设计：

1. **沿示向度前进，不做大角度横移**。首版 dog-leg 横向平移会走出有效接收半径拿到
   no_signal，清除率只有 45%。改为沿示向度方向逼近后升到 81%。
2. **约 51% 的干扰源在原点收不到信号**，环形补扫是主路径而非兜底。按"最坏覆盖间隙
   < 接收半径下限 1000 m"选出原点 + 1250 m×12 站位（间隙 670 m），比双环 23 站位省 43%。
3. **检测预算必须分搜索段和归航段**。曾有案例已测到距真值 413 m 的示向度、候选压到
   2 个格点，却因共用预算被判定放弃。
4. **定向源不靠加密站位**（37 站位才 98.7% 可见率，成本翻倍），改用"沉默即约束"推理
   压缩候选区 + 对候选格点盲清除（`/clear` 不受辐射方向限制）。

## 现在做出来的东西是什么水准

先说结论：**这是一份「能拿高分、冲一等奖有底气」的工程与规格底座，但离"锁定国一"还差最后一公里——那一公里主要在论文成稿与正式测试的现场执行，不在代码。**

**已经达到的水准（工程与方法层面，属第一梯队）：**

- **算法与策略本身有竞争力**：Q3 离线 60/60 全清、Q4 40/40 全清，官方演练与离线偏差仅 5–10%，说明策略在真实评测下站得住。评分指标（平均定位清除时间）有明确、可复现的优化依据（移动占 81%→就近贪心 + 沿示向度逼近）。
- **结论都有证据链**：覆盖站位、原点盲区 51%、定向可见率天花板等关键论断都由数值实验支撑，而非拍脑袋；这正是评委在"模型合理性 + 结果可信度"上最看重的。
- **少见的工程严谨度**：正式的设计→需求→任务规格、需求逐条可追溯、8 条正确性性质用 hypothesis 兜底、204 项测试全绿、协议健壮性（越界/400/409/重试/幂等）齐全、去标识与支撑材料合规——在竞赛作品里这种规格化程度属于**明显加分项**，也把"结果不可复现""踩合规红线"这类容易致命的风险压到很低。
- **Q1/Q2 的理论深度**：直径算法给了凸集极点引理证明、外接圆覆盖用正三角形反例 + Jung 上界收口，属于评委喜欢看到的"把小问题做透"。

**离国一还差的（决定名次的关键，且不在代码）：**

1. **论文成稿**：目前是四个 `paper/*.md` 章节 + 配图脚本，还**不是一篇按格式规范排版、有摘要/建模假设/符号表/结果分析/灵敏度/优缺点的完整论文**。国赛评审看的是论文，代码再好也要靠论文表达出来——这是当前最大的一块短板。
2. **正式测试的现场执行**：Q3/Q4 各只有 3 次正式机会、9/13 17:30 后不能开新测试。演练成绩好不等于正式成绩好，现场网络、时间窗、`/enter` 时机都可能翻车；表 1 的正式数据还没有。
3. **灵敏度与稳健性论证**：策略里不少常量（如 1250 m 环、`approach_fraction=0.62`、盲清除阈值）是调优所得，论文里需要给出参数灵敏度分析，否则评委会质疑"是不是过拟合到仿真器"。

**一句话定位**：代码与方法学已经是**能支撑国一的底座**（甚至强于多数队伍），能不能真拿到国一，取决于把这套东西**写成一篇高质量论文**并**在正式测试里稳定复现成绩**。把 `paper/` 的章节整合排版 + 补一节参数灵敏度 + 现场稳妥打完 3 次正式测试，就具备冲一等奖的完整条件。
