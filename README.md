# 无线电干扰源的快速自动定位与清除

**2026 高教社杯全国大学生数学建模竞赛（CUMCM）B 题 · 全国二等奖**

一只机器狗在半径 1800 m 的圆形区域内搜索未知数量的无线电干扰源，只有一种传感器：静止检测 5 s，得到带 ±1° 误差的示向度，或"无信号"，或"过近"。清除半径 20 m。评分指标是**平均定位清除时间**（总虚拟时间 / 清除个数），越短越好。

仓库包含完整参赛工作：离线仿真器、四问的解析与算法、最终交付策略、论文源与构建脚本、官方模拟器实测日志（脱敏）、358 项回归测试。

## 方法

四个子问题的结论都来自可证明的几何性质，而非黑盒调参。

**问题 1 — 定位区域的直径与覆盖。** 证明有限点集的定位区域直径等于其凸包极点间的最大距离，给出 $O(n\log n)$ 算法；并证明"以定位区域直径为直径作圆"一般不能覆盖该区域：正三角形取任一边为直径时，对顶点落在圆外 $0.366a$ 处。由 Jung 定理，覆盖半径介于 $[d/2,\ d/\sqrt3]$ 且上界可达，故最坏情形需放大 $2/\sqrt3\approx1.155$ 倍。一次清除的正确判据是最小外接圆半径不超过 20 m。

**问题 2 — 第二观测点选点。** 以定位区域面积最小为目标，导出交会角越接近 90° 面积越小的结论；基线长度存在精度与耗时的权衡。给出四类硬约束（区域内、接收稳健、交会角可用、基线充足）的交集作为候选区，中心场景下候选区仅占目标区域 0.38%，推荐点的 2000 次蒙特卡洛校验证实定位区域无界概率为零。

**问题 3 — 覆盖式搜索。** 实测发现约 51% 的源在原点不可见，因此把环形补扫确立为主路径而非兜底。按"最坏覆盖间隙 < 接收半径下限 1000 m"设计覆盖环，取 $R=1150$ m、6 站位配 12 相位择优；900 局配对实验确认该配置较初始 12 站位方案降低指标 4.5%–10.0%、检测次数减少 29%。

**问题 4 — 定向源。** 引入内环 1000 m×7、外环 1870 m×12 的双环布局。外环半径由定向源半平面可见性的几何下界 $R_o \ge R_A/\cos(\pi/12)$ 确定，即 $R_o \ge 1863.5$ m；这是硬约束，不是调参结果。把"无信号"当作约束压缩（位置, 朝向）候选网格，再对候选格点直接盲清除——清除只看距离，与辐射方向无关。

**优化方法论。** 移动占总虚拟时间约 80%，是唯一数量级级别的杠杆。用分段归因定位到归航空驶占移动的 68.1%，改进巡回排序（最近邻 + 2-opt + Or-opt）与归航策略后，绕路倍数从 2.58 降到 1.27。参数标定采用配对检验，系统否决了五项表面有效实则不符的方案。

## 一个值得记下的错误

开发中期曾把外环半径从 1870 m 缩到 1800 m（即区域半径），依据是"最坏覆盖间隙 + 巡回长度 + 240 局随机场景配对"，三项指标同向改善、两档满清零退化。

**这是错的。** 贴边且辐射轴径向朝外的定向源，其 180° 扇区只含更外侧的点，站位必须落在过源的切线之外。按几何条件构造的 60 局压力样本上，1800 m 版本 **60/60 局全部漏源，且耗时也更差**（417.53 s vs 392.69 s）——漏清会耗尽射线盲扫与就近复活的兜底预算，所以这不是速度换清除率的权衡，两个维度同时更差。

教训有普适性：**改动只影响稀有子群体时，随机场景的均值配对检验没有检出能力**，必须按机制构造针对该子群体的压力样本。这条几何下界现在写成了断言（`src/test_q4_outer_radius.py`），防止再被人凭均值指标缩回去。详见论文 7.13 节与 `paper/b_optimization_section.md`。

## 快速开始

交付策略本身只用 Python 标准库，不需要任何第三方包。以下命令用于复现论文中的离线结果。

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # pytest / hypothesis / numpy / scipy

# 离线彩排：问题 3（60 局）、问题 4（40 局，5 个定向源）
python -m src.b_sim.rehearse --episodes 60 --seed-start 5000
python -m src.b_sim.rehearse --episodes 40 --seed-start 7001 --directional 5

# 全量回归（358 项，约 8 分钟）
pytest src -q
```

复现论文中的具体数字（如留出集 260 局）：

```bash
python -m src.b_sim.tune --episodes 200                     # 单点评估（并行）
python -m src.b_q1_counterexample                            # Q1 覆盖反例（精确有理数）
python -m src.b_boundary_matrix --seeds 21000                # 边界压力矩阵
```

## 工程实践

- **358 项测试**：172 项单元/回归、33 项面向性质测试（hypothesis）、其余覆盖策略几何、文档与代码一致性、论文数字可溯源、zip 字节可复现。
- **一致性断言**：`test_docs_match_code.py` 检查 README 声称的参数与代码常量是否一致；`test_paper_citations.py` 检查论文引用文件存在且成绩可复算；`test_figures_match_strategy.py` 检查配图与策略参数联动。改参数不重生成图，测试会红。
- **脱敏**：官方日志内嵌真实队号与 `server_ticket`，只有脱敏件入库。`src/sanitize_official_run.py` 替换队号与 Windows 用户名、把服务端密钥字段置零，并用**独立清单**复核（不复用替换清单，否则摘掉一个字段就自动跳过检查）。
- **交付包防漂移**：`dist_windows/` 由脚本从 `src/b_sim/` 同步，`--check` 校验字节一致；zip 构建可复现（固定时间戳与顺序）。
- **赛日总闸**：`python scripts/raceday_preflight.py` 一条命令跑完五道门禁，任一不过即非零退出。

## 开发过程

148 个提交、12 个 PR，2026-09-10 至 09-13。提交信息记录了每次假设、实验与否决原因；`state/decision_log.json` 是决策台账，`paper/b_optimization_section.md`（696 行）保存了全部被证伪方案的实测数据。

被否决的方案包括：检测预算扩张（前提不成立，清除率已饱和）、批量归航、survey-first 顺序、沉默覆盖认证（判空误判率 11.43% 不可接受）、外环缩到 1800 m（见上文）。保留这些记录的理由很简单：删掉它们，"为什么改"就失去凭证。

## 已知局限

1. **`near` 分支未经真实验证。** 逻辑正确（收到 `near` 立即清除，全仓单一调用点），但官方演练 2415 次检测里 `near` 出现 0 次，只在离线 mock 走到过。
2. **完全认证在问题 4 不可行。** 47 站位、21.5 km 巡回仍剩 120 格未覆盖，所以交付版是 99.81% 而非 100% 的认证覆盖，靠盲清除兜底。
3. **离线仿真器与官方模拟器存在偏差**（Q3 约 5.4%、Q4 约 9.6%），所有结论以官方实测为准。
