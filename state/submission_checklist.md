- [ ] Team leader account is ready; MD5 order is paper first, supporting material second.
- [ ] Final paper is `校内编号.pdf`, PDF, no larger than 20 MiB.

      purpose + details in supporting material. Evidence: `paper/main.md`, rendered p24.
- [ ] 台账 `state/claim_evidence.csv` 无「待核实」。2026-09-13 已清零：40 已核实、
      1 已失效（旧站位结构条目）、2 待官方实测（共址补测 Q4 两档，收益与官方—离线偏差同量级）。
- [x] `AI工具使用详情.pdf` is generated by `python -m src.build_ai_usage_pdf` (filename is
      fixed by Article 4 — no space before 工具). Covers all four required items; source of
      truth is `state/ai_usage_log.csv` (17 entries). Evidence: `paper/build/`, 5 pages, A4.
- [ ] That PDF is actually placed inside the RAR before stage-2 upload.
- [ ] Complete runnable source code is in both the paper appendix and supporting material.
- [ ] No school, names, team number, advisor, or related metadata appears anywhere in paper/RAR/staging filenames or content.
- [ ] PDF rendering, formulas, fonts, symbols, figures, pagination, and document metadata manually checked.
- [ ] **PDF 一旦生成就定稿，不要为任何理由重跑构建。** 实测同一份 Markdown 连续构建两次，
      PDF 字节数相同但 MD5 不同（LibreOffice 会写入 CreationDate，且抹掉时间戳后仍有差异），
      即 PDF **无法字节复现**。第一阶段交完 MD5 后重跑一次构建，哈希立刻失效。
- [ ] `python scripts/submission_hashes.py freeze <论文PDF> <支撑RAR>` 在提交前冻结基线
      （写入 `state/submission_hashes.json`）。这只是本地旁路记录 —— 正式 MD5 必须由
      竞赛客户端生成、由队长账号上传。客户端第一阶段提交后，不要打开/编辑/保存/另存任一文件。
- [ ] `python scripts/submission_hashes.py verify` 返回 0 后，再在客户端第二阶段由队长上传。
      返回 1 表示文件已改动，会打印基线与当前的 md5 及字节数；此时要么恢复原文件，
      要么在客户端重新走第一阶段。
